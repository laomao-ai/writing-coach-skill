# 体检报告：《六个原创排版主题，各自适合写什么》

按公众号长文看。只出报告，正文没动。

**总评**：这篇基本不用改。标题提的问题（各自适合写什么）在第 02 节一张表里就答完了，后面每节都在推进，结尾落到“先挑一个试试”。要说先处理哪里，是几个对新读者不太友好的说法，以及“公众号常用的一组参数”缺一句来源。

## 五关评分
| 关 | 分（0–4） | 依据（引原文） |
|---|---|---|
| ① 立意 | 4 | 标题「六个原创排版主题，各自适合写什么」，第 02 节「按文章类型选，不按颜色选」直接作答，结尾「先挑一个系列试试」兑现 |
| ② 结构 | 4 | 小标题 01–06 连起来读是一条完整主线：为什么自己画 → 怎么选 → 样例 → 参数 → 组件 → 怎么用 |
| ③ 证据 | 3 | 关键说法大多是自家产品事实；只有「我们以公众号常用的一组参数为基准」的“常用”没有给出依据 |
| ④ 语言 | 4 | 具体、简洁，如「白皮故意放得很松，墨刊故意收得很紧」；有你自己的语气，没有套话 |
| ⑤ 读者 | 4 | 开头「上一篇发出后，问得最多的一个问题是：能不能换个样子？」三句内说清和读者的关系；结尾给了下一步 |
| 合计 | 19/20 | |

## P0 必改
- 无。

## P1 建议改
- [第 04 节]「我们以公众号常用的一组参数为基准：正文 15px、行高 1.75」→ “常用”是公共断言，但没说依据（平台默认值？你们统计过的样本？经验？）→ 补一句来源，或改成你能确认的说法，比如说明这组数值是怎么来的。（状态：待核实，缺来源）
- [第 01 节]「上一篇的排版，底子来自一个开源项目」→ 提到了别人的工作，但没写项目名 → 建议写出项目名或链接。既是对原作者的尊重，也能让读者理解“为什么要重新画”。
- [第 02 节表格]「白皮 · 头部IP」与「AI 工具实测」「PART 章节头」→ 中英文之间加不加空格，全文不统一 → 二选一统一即可。如果“头部IP”是固定的系列名，可以不动，只保证全文写法一致。

## P2 可选
- [第 02 节]「白皮 · 头部IP」→ 新读者不一定懂“头部IP”指什么风格，表里的“适合写什么”是 AI 工具实测，和“头部IP”对不上 → 可选：在表里或样例里补一句说明。
- [第 06 节]「把 Markdown 交给 Agent，告诉它用哪个主题」→ 没读过上一篇的读者，不知道这里的 Agent 指什么 → 可选：补半句，或加一个指向上一篇的链接。
- [第 05 节]「所以主题实验室里有三种预览」→ 上一句是“组件让这一段更容易读懂”，和“有三种预览”之间的因果比较松 → 可选：去掉“所以”，或补一句两者的关系。
- [第 03 节]「所以每个系列都配了一篇短样例」→ 和开头「还配了一篇按它的长处写的短样例」、本节标题意思重复 → 可选：这里只留“题材按它最擅长的来选”这层新信息。

## 待补证据清单
| 断言 | 需要什么证据 | 建议检索 |
|---|---|---|
| 公众号常用参数：15px / 1.75 / 1px / 24px / 16px | 数值来源：平台默认值、官方编辑器设置、你们的样本统计，或明确说是你们的经验值 | 查公众号编辑器默认样式和官方文档；如果是经验值，直接写明即可 |
| 上一篇排版的底子来自一个开源项目 | 项目名、链接、许可 | 你们自己的记录或上一篇原文 |
| 组件库有 24 个组件、六个系列 × 三种配色 | 自家产品数据，不需要外部出处 | 发布前对照组件库实际数量自己核对一下；摘要里的“十八种配色”和正文 6 × 3 一致 |

## 没问题的部分
- 标题、摘要、首段说法一致：六个系列、十八种配色、按文章类型挑，没有标题承诺而正文没兑现的情况。
- 第 02 节的表格：“适合写什么”和“一眼认出它”两列，读者选主题需要的信息都在里面。
- 第 03 节的理由「同一篇文章排六遍，只能看出颜色不同」：一句话说清了为什么每个系列配不同样例。
- 第 04 节的参数表和「贴不贴边，要看这个系列想给读者什么感觉」：有数字，也有取舍的理由。
- 第 06 节的检查清单和“关于滑动效果”的说明：把可能遇到的问题提前讲了，可信度高。
- 结尾的互动提问「你下一篇文章，最想用哪个系列来排？」和全文直接相关，不是套话。
