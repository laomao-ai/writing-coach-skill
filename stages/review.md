# ④ 体检

目标：用五关给稿子打分，指出每个问题在哪、怎么改。

第一步先判断文体（masters/README.md 路由表），报告开头写明“文体：××”；然后按五关过一遍（评分锚点见 gates/README.md）：

| 关 | 检查清单 | 方法卡 |
|---|---|---|
| ① 立意 | checklists/logic.md 第 1 组 | feynman、zettelkasten |
| ② 结构 | checklists/logic.md 第 2 组 | pyramid、scqa、inverted-pyramid |
| ③ 证据 | checklists/facts.md | 观点评论用 harvard |
| ④ 语言 | checklists/ai-flavor-zh.md、checklists/typo-zh.md | 全局：余光中卡；按文体：williams、iceberg |
| ⑤ 读者 | checklists/logic.md 第 3 组 | success |

每关引用的大师只从该文体的名单里选。体检结束时，针对得分最低的一关，从 drills/README.md 推荐一个练法。

## 规则
1. **每个问题带原文定位**（段落 + 原句，不超过 30 字）和改法。
2. **严重度**：P0 = 事实错误、论证支点不成立；P1 = 证据缺失、论证薄弱、错别字；P2 = 语言、节奏、措辞。
3. **事实状态**：已核实（给出处）/ 待核实（写清缺什么）/ 疑似错误（写出依据）。没有联网检索时，依据又不在稿子内部，最多写到“待核实”。个人经历不要求外部出处。
4. **稿子已经好就直说**：P0 写“无”，把篇幅留给“写得好的部分”。分数严格按 gates/README.md 的锚点给，满足 4 分锚点就给 4，不因为还能挑出 P2 小问题就扣分。
5. 用户只要看某几关，只详评那几关。
6. 作者声明有个人风格时，语言关只提示，不建议改写。

报告格式见 templates/audit-report.md。

## 请大师会诊
用户说“请大师看看”或点名某几位：按路由表请这一类的大师（最多 3 位，各一句话说明为什么请他），点名的照请。每位大师从卡上“会问你的问题”和“能查出的问题”出发，挑最多 3 条，每条：原文定位 → 依据哪条主张 → 改法或追问。大师之间意见冲突时摆出来，说明各自适合什么情况。结尾给 3 条按优先级排的处方。格式见 templates/consult-report.md。卡里没有的主张不替大师发挥，不写“某某会说……”。

## 只核事实
用户只要查数字和引语：跳过评分，逐条列出数字、日期、人名机构、引语、研究结论及位置，标状态，附检索建议。

## 评分块（给别的 Agent 读）
用户或上游流程要机器可读的结果时，在报告末尾附：

```json
{"genre": "通用", "scores": {"立意": 4, "结构": 4, "证据": 3, "语言": 4, "读者": 4}, "total": 19, "p0": 0, "p1": 3, "p2": 4, "weakest": "证据", "drill": "刻意练习"}
```
