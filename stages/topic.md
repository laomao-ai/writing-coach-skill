# ① 选题立意

目标：从一个方向，找到值得写、写得出彩的那个角度，并收成一句话立意。

## 流程
1. **认文体**：按 masters/README.md 的路由表判断这篇大概属于哪一类，请这一类里管立意的大师（如观点评论请胡适、鲁迅；文化读书请刘勰；通用请津瑟）。
2. **出候选**：给 3 个不同角度的选题。每个写清：
   - 一句话立意（读者读完会相信什么、得到什么）
   - 目标读者
   - 为什么现在值得写 / 作者的独特之处（用户给过经历和材料就用上）
   - 判定文体
3. **推荐一个**，说明理由（立意最清楚、读者最明确、材料最足，选其一说透）。
4. **往上拔一层：逐层穿透**。候选出来后，挑推荐的那个往下拆：“X 的核心是 Y，不是 Z”，连拆三四层，直到拆出一个读者没想到、又一听就认的判断。大家都想得到的那层是钩子，拆到底的那层才是立意。拆出来的层次可以直接变成文章骨架，层数控制在 3–4 层，多了读者记不住。
   - 例：排版的核心是让人读下去，不是好看 → 读下去的核心是内容，不是样式 → 内容的核心是想清楚，不是堆字数 → 想清楚的核心是练习反馈，不是读过就算。
   - 检查：拆到最后一层，读者会不会“哦，原来是这样”？如果最后一层还是常识，再拆一层或换个起点。
5. **可选：写前追问**。用户想把立意想得更透时，按所请大师卡上“会问你的问题”追问，每轮 ≤3 问，问到能写出一句话立意为止。追问写成“按胡适‘言之有物’这条：删掉形容词，你这篇还剩哪一句实在的判断？”，不写“胡适会问你……”。

## 产出：立意卡
一句话主题 / 目标读者 / 读者读完会怎样 / 文体 / 已有材料 / 还需要的材料

接下来可进 ② 标题框架。

## 检查（立意关）
- 能不能一句话说清这篇要读者相信什么？
- 标题能承诺的，正文能兑现吗？
- 选题服务读者，不靠制造焦虑或标题党撑。
